# 系统通用调优

> 状态：architecture draft；与 workload 使用不同思路已 confirmed。

## 目标

在没有真实业务 workload 的情况下，用受控、可重复的标准压力寻找稳健的 guest OS 基础配置，并输出通用 Profile。

## 流程

1. 采集配置和环境，冻结原始基线。
2. 校准标准压力的稳定性和观察者开销。
3. 按 CPU、内存与 NUMA、存储、网络等组件运行独立测试。
4. 在单组件允许域内生成、施加和验证候选。
5. 用本组件主指标评价，用其他组件指标做退化门禁。
6. 保存每个组件的 best observed 和证据充分性。
7. 组合候选后运行混合标准压力，检查交互和回归。
8. 通过全部门禁后形成通用 Profile；默认仍回滚，显式批准后才保留。

## 评分边界

- 先保留组件分数组，不假设固定跨组件总权重。
- 组件局部最优不能直接相加或拼接成全局最优。
- 稳定性、安全、正确性和跨组件退化是门禁，不是可被补偿的负权重。
- 结果只能宣称适用于已测环境、压力协议和搜索预算。

## 标准压力要求

标准压力 MUST：

- 声明主要刺激的组件与已知跨组件影响。
- 有固定输入、阶段、持续时间、清理和缓存状态协议。
- 能在目标环境稳定出数后才能进入搜索。
- 与真实 workload 明确区分，不把探针提升冒充业务提升。

具体组件指标、压力工具和搜索参数在原始指标盘点完成语义验证后确定。
