## 1. 一句话定位

System Optimizer = **若干个独立、简单的组件优化器（CPU/内存/网络/存储/NUMA…）**
**被一个总优化器引擎管理包装**；引擎只做调度、判断、打分三件事，通过调用底层
共享门禁对组件产出的候选做裁决；组件的本质是"在压力器构建的负载下，由采集器
采集指标，用已写好的公式把指标分析映射成配置建议"；全程基于显式公式，搜索没有
产生优化时由回退器把系统退回原状，未能优化到的指标进入缓存层避免重复浪费预算。

## 3. 两种运行情境与结束门禁

优化器有两条工作相位，按"系统上有没有真实任务负载"划分：

### 3.1 静态优化（系统初始，无真实任务负载）

- 状态：机器空闲或刚交付，优化器独占目标机。
- 动作：一次性、离线地确定初始系统配置——L3 合成压力逐组件探测，L4 采集，
  L5 公式映射出配置建议，L8 门禁验证，产出**初始 Profile**（或"保持默认"）。
- 产出交接物：初始 Profile、各组件冻结基线（B_m/scale_m/MDE_m）、CV 稳定性
  门限、guard 基线、负缓存初值。
- 性质：跑完即止，不留常驻进程。

### 3.2 动态优化（任务启动后，真实负载压力下）

- 状态：真实 workload 在跑，优化器在负载下观测。
- **负载供给边界（SO-D020）**：动态相位的负载由任务/测试侧**外部提供**
  （第一版以 stress-ng 等基础套件作业务负载替身）；引擎**不主动调用压力
  工具造载**——那是静态相位 L3 的职责。详见 workload-tuning.md D0。
- 目标：以任务自身指标（SLO/吞吐/尾延迟）为最终目标函数；组件微指标只做
  归因线索，不做裁决（"组件降配但整体不变/更好"在这里有合法胜出路径）。
- 动作：负载下观测（L4）→ 引擎打分选组件（L8）→ 小步干预 → 真实负载中
  复验 → 回退或保留。
- 干预约束：单轮变更数上限、负载窗口选择、观测与施加分离。

### 3.3 结束门禁（动态相位的第一等约束）

动态优化必须有显式终点，防止无限干预、振荡追噪、收益递减不停手。停止原因
必须是 S10 枚举的显式状态之一，至少覆盖：

1. 目标达成：任务 SLO/目标指标满足并保持 N 个观测窗；
2. 收敛：连续 K 轮候选收益置信下界 ≤ 0；
3. 预算：变更次数/干预墙钟/风险额度耗尽；
4. 安全触发：任一变更导致任务指标显著退化 → 立即回滚并停止本相位；
5. 负载消失/剧变：当前证据链失效 → 停止。

结束 ≠ 永久关闭：负载模式显著变化可申请重新进入优化（重激活判据 open）。
静态相位的 Profile 在动态相位是初始值不是约束，动态相位有权改掉它。

## 4. 引擎主循环（完整流程）

```
loop:
  1. 取各组件指标/测量批次（静态：L3 加压后采集；动态：负载下观测）
  2. 打分器：S4 公式算各组件 (P_m, D_m, Persistence, Confidence)
     → 组件优先级
  3. 调度器：查 L7 负缓存（同身份已证无效 → 跳过），
     按优先级选出本轮组件 + 候选（公式映射优先，搜索兜底）
  4. 判断器：S0 可比性 → S2 硬门禁 → （施加后）S7 接受条件
  5. L1 底座施加 + L3/L4 再压再采 → 结果回流打分器
  6. 有效且有收益 → 进入 S8 排名 / S9 晋升复验；
     无效或无收益 → 结果写入 L7 负缓存，L6 回退器执行回退
  7. S10 停止条件触发 → L6 相位级回退确认系统=基线 → 收工
  8. （运行期 U_regression 报警 → L6 退化级回退 last-good）
```

## 7. 与现有代码的差距与建议实现顺序

1. **L8 引擎骨架**：调度器/判断器/打分器三件套，把 S0/S2/S5/S6/S7 的现有散落
   实现收编为引擎统一调用；组件优化器降格为"搜索+映射+上报"。

   并将 P/D/A/Q/T 与 M9 存量证据迁移合并为一次 schema 版本事件。
3. **L4 采集器**：每组件定义指标采集集，压/采解耦。
4. **S8 + L6c**：核心执行桥与 G5 CLI 生命周期、证据落盘、租约/attention 接线均已完成；下一步是真实目标退化演练。
5. **S9 组合复验**：合同和动态复验生产者已完成；真实已接受候选的跨环境验证仍开放。
6. **L7 负缓存**：身份绑定 + 证据挂钩 + 失效规则（见 §2 红线）。
7. **S10 相位级结束门禁 + 动态相位**：静态闭环稳定后进入动态优化实现。

顺序原则：先把"判断与打分的裁决权"收进引擎（1/2），再补观测（3）、系统级
裁决（4/5），最后缓存（6）与动态相位（7）。负缓存虽列为第 6 步，其架构位置
（L7）与红线（§2）现在即定死，防止后补时破坏证据链。

## 8. 数据流与证据原则（继承 v1，继续有效）

- 原始采集事实不可被派生分数覆盖。
- 每个派生值引用输入指标、公式版本和比较基准（formula_id + 输入 digest）。
- 每个候选引用配置快照、workload、阶段、环境和工具身份。
- 通用（静态）Profile 与场景（动态）Profile 明确区分，不默认跨环境可移植。
- 所有最终结论可回到原始证据重算。
- 任务生命周期：created → preflight → baseline → probing/observing →
  diagnosing → applying → verifying → measuring → deciding →
  rollback-or-keep → completed；任一阶段可进 rejected/failed/cancelled/
  needs-attention；只有完成对账和回滚验证的任务才能宣称目标已恢复。
- 优化任务结束后不得继续自动改参（对应 §3.3 结束门禁）。

## 9. 明确不做（继承 v1，缓存条目已修订）

- always-on 在线自治控制。
- 按 workload 阶段实时切换 Profile（动态相位是受结束门禁约束的有限干预，
  不是常驻切换器）。
- 修改 hypervisor/宿主机、应用代码、编译器或 kernel patch。
- 未授权购买、启动或销毁云资源。
- 用 RL/LLM 绕过候选、安全门禁或证据规则。
