# System Optimizer 路线图

> 状态：planning draft；阶段顺序用于讨论，不代表工期承诺。

当前实际实现与本路线图的偏移必须以
[2026-08-23 实现重新基线](implementation-rebaseline-2026-08-23.md)为准；提前出现的
M2/M3 代码切片不代表对应里程碑已经验收。

## R0：架构重新基线与文档迁移

交付：

- 当前文档入口、决策日志、术语、规范和协作协议。
- 共同配置底座、通用调优、workload 调优和下钻架构。
- 指标、评分、安全和恢复契约草案。
- 旧方案与原始指标盘点无损迁移。
- 新里程碑和验收标准。

出口：用户确认新总线；open decisions 不得伪装为默认实现。

## M1：配置资产与安全底座

目标：先完成“知道系统现在是什么、用户想改成什么、实际是否生效”。

交付：

- 配置发现与全量采集。
- 当前/期望/生效/持久化/所有权状态。
- 目标能力和动态合法域。
- 用户手动修改、dry-run、diff、snapshot、apply、verify、rollback。
- 单目标写租约与崩溃对账。
- 修复两个已知 A 级安全问题。
- simulated E2E 和独立 basetemp 全量回归。

出口：不依赖任何优化算法，也能安全采集、人工修改和恢复配置。

## M2：通用标准压力调优

交付：

- CPU、内存与 NUMA、存储、网络的组件树和经验证指标合同。
- 每个组件的标准压力、阶段、清理和稳定性协议。
- 组件候选搜索、跨组件门禁和组合复验。
- 多轮搜索控制器：历史反馈、周期基线、共享 attempt/wall-time 预算和结构化停止原因。
- 通用 Profile、报告和 simulated demo。

出口：能在受控环境有限运行并明确报告 best observed、稳定性、适用边界和回滚状态。

多轮控制器的实现基线与剩余工作见
[多轮自动闭环开发基线](multi-round-closed-loop-2026-08-23.md)。单候选安全执行实录不再作为
“自动搜索闭环完成”的证据。

## M3：workload 动态观测与下钻调优

交付：

- workload 业务目标、SLO、阶段和输入合同。
- L0/L1 低开销采集与真实开销验证方法。
- L2/L3 触发式微指标采集。
- 组件路由、组件内二维优先级和多假设记录。
- 干预复验、业务候选评价和动态预算重分配。
- 场景 Profile 与相对原始基线、通用 Profile 的双重报告。

出口：系统微指标只负责诊断，最终结论能够回到业务实测证据。

## M4：平台集成与扩展安全

交付候选：API、事件投影、权限、审批、远程目标、可选多节点协议和 UI。真实后端必须按环境逐层完成可获取、可构建、稳定出数和区分度验证。

## M5：交付收尾

交付：完整运行手册、可复现实录、schema 版本、迁移说明、失败演练、文档/代码/测试状态核对和已知限制。

## M6：优化器过程优化

仅在 M1–M5 功能和证据合同稳定后开始：

- 采集结果缓存。
- 中间测量与候选结果复用。
- 增量下钻和快速探针选择。
- 缓存身份、有效期、失效和跨环境可信度。

M6 不得反向削弱真实验证、安全门禁或审计可追溯性。
